# PATH — the tested route from here to the finished engine
*2026-09-02. One document, in execution order, that says for every step: what
goes in, what comes out, the exact test that proves it, who does it, and how
long. Builds on the existing repo; nothing is started fresh. Every step ends
with `pytest -q` green and a commit on `v2-day1`.*

## 0. Build on or start fresh — decided
**Build on.** The irreplaceable assets are already here and tested: the corpus
(313 events, two-source, gated), 7,999 measured transmission edges, 567 series
and 466k observations back to 1946, the pre-registration and red-team record,
150+ tests, and the surfaces. Starting fresh would discard the only part that
took months and cannot be regenerated by code. What gets **replaced** is
narrow and named below; what gets **kept** is everything else.

| keep as-is | keep, extend | replace | retire |
|---|---|---|---|
| corpus + codebooks; `event_study.py`; edges; series loaders; integrity regime; `big_moves.py`; `materiality.py`; `ledger.py`; `reader.py`; `challenge.py`; `api_v2.py`/`app.html`; tests | `story_read.py` (reads from the state engine); `feed_build.py`; `acceptance_v2.py` | `escalation.py` similarity over 9 hand fields → state-vector similarity; `sr_outcome_*` corpus-derived labels → independent codings; `walk_forward.py` → `walk.py` per protocol | `workbench.html`, `deconstruct.py`/`triage.py` on the v2 surfaces (legacy only) |

## 1. The route (12 steps)

### Step 1 — Codebook before loaders (Claude Code A · ½ day)
- In: WORLD_STATE_FRAMEWORK.md §3, WORLD_STATE_SOURCES.md.
- Out: `WORLD_STATE_CODEBOOK.md` — one line per field: block, field, unit,
  resolution, source + URL, coverage, licence, rule id. Committed **before**
  any loader.
- Test: `tests/test_codebook.py` parses the table; every field has all 8
  columns; no source URL outside the register.

### Step 2 — State panel loaders (Claude Code A · 5 days)
- In: the register. Out: `state_panel(entity_id, field, obs_date, value, unit,
  source, vintage, retrieved_at)`; `src/state/<source>.py` ×15; licence-
  restricted files gitignored with a README stub.
- Tests (one file per loader, run offline against a cached fixture + one live
  smoke when network exists): a published value reproduces exactly (e.g. EIA
  surplus capacity 1985 = 11.3 mb/d; NMC CINC USA 2000; ICB crisis count 512;
  GPRH exists for 1914-08; RCLC1 first date 1983-03-30; WTISPLC 1974-01 =
  10.11). Vintage column never null.
- Acceptance: `python3 src/state/status.py` prints coverage per block per
  decade; ≥ 12 loaders green.

### Step 3 — State-at-event join (Claude Code A · 1 day)
- Out: `situation_state(event_id, field, value, vintage, source)`;
  `state_at(date)`.
- Tests: `test_vintage_rule.py` — a value with vintage > t is invisible at t;
  `test_join_coverage.py` — every corpus event has a row; coverage per block
  reported for 1946–86 and 1987→ (numbers published, not asserted).

### Step 4 — Independent outcomes (Claude Code A · 2 days, then Joe · 1 day)
- Out: `event_outcomes(event_id, source, field, value)` from ICB (VIOL,
  SEVVIOSY, FOROUT, OUTESR, GPINV, GLOBACTM), MID (hostlev, fatality), UCDP
  (intensity, BRD); registered mapping to the four branches
  (`OUTCOME_MAPPING.md`, committed first); κ against `sr_outcome_90`.
- Tests: mapping is deterministic and total; κ computed on synthetic data
  matches hand value; every geopolitical event has ≥ 1 independent source or
  is flagged `no_independent_outcome`.
- Joe gate: audit 60 disagreements → `data/audits/outcome_audit_60.csv`.
  Rule: if κ < 0.6, our branches are replaced by the independent ones.

### Step 5 — Corpus completion, first pass (extractor + Joe · 2 weeks, parallel)
- In: Big Moves "no identified event" list (15 daily + 1 monthly); ICB crises
  1946–87 involving oil states/chokepoints; OPEC conference record.
- Out: candidate events through the existing admission gates
  (`admit_events.py`), Joe approves; dossier fields for escalation classes as
  verbatim dated quotes.
- Tests: no event enters without two sources (existing tests); vintage of
  every dossier field ≤ event date.
- Acceptance: ≥ 120 sourced events 1946–86; ≥ 25 non-unknown state fields per
  1987+ event.

### Step 6 — Similarity on the state (Claude Code B · 2 days)
- Out: `src/engine/similarity.py`: block-wise weighted distance;
  standardization within the information set at t; unknowns excluded and
  counted; threshold → no precedent; per-block contributions.
- Tests: identical states → distance 0; a field unknown on either side does
  not change distance; standardization uses only data ≤ t (assert by
  injecting a future outlier); threshold fires below `RETRIEVE_MIN`.

### Step 7 — The read (Claude Code B · 2 days)
- Out: `src/engine/read.py` returning G/P/F distributions with n, propagation
  per branch through `edges`, differencing table with evidence status,
  `data/walk_forward/menu.json` (≤12 weightings) written and committed.
- Tests: read on `abqaiq_attack_2019` uses only analogs dated before it; sums
  of branch counts equal n; every hop carries n; "no adequate precedent" path
  returns no numbers.

### Step 8 — The walk (Claude Code B · 5 days)
- Out: `src/walk.py` per WALK_FORWARD_PROTOCOL.md; `reads.jsonl` sealed;
  `scores.jsonl`; `weights.jsonl`; `summary.json`; figures.
- Tests: sealing (hash of read precedes outcome lookup; tampering detected);
  Brier/log/CRPS/pinball on synthetic distributions match closed-form values;
  Hedge regret on a toy sequence ≤ bound; DM/HLN reproduces a textbook
  example; leakage test — a run with filtration broken must differ from the
  sealed run (asserted); placebo skill ≈ 0 within CI on synthetic null data.
- Acceptance: `summary.json` published as computed; VALIDATED gated on §7
  incl. Step 4 audit flag.

### Step 9 — Desk on the engine (Claude Code A · 3 days)
- Out: Story page and Challenge read from `engine/`; Ledger engine board from
  `summary.json`; new **Walk** page (pick a date → state → read → outcome →
  score → learning curve).
- Tests: TestClient on `/api/story?id=`, `/api/challenge`, `/api/walk?date=`;
  jsdom render of app.html with recorded API fixtures (already in place for
  Feed/Story/Ledger — extend).

### Step 10 — The three demos (Cowork + Joe · 2 days)
- 2001-09-11, 1990-08-02, 2026-03-04 from sealed inputs, end to end.
- Test: `tests/test_demo_911.py` — the state vector has the fields listed in
  WORLD_STATE_SOURCES §7 either valued (vintage ≤ date) or "unknown"; the read
  is sealed before the outcome is read; the score matches `scores.jsonl`.

### Step 11 — Release v3.0 (Claude Code A · 1 day)
- `acceptance_v2.py` extended to S1–S8 checks; README/STATE/DATA_DICTIONARY
  regenerated; tag `v3.0`; MORNING_NOTE replaced by RELEASE_NOTE.

### Step 12 — Paper and deployment (Joe + Cowork · 1 week)
- 8–10 pages: question, spine, method, walk results (whatever they say),
  Big Moves findings, limits. Deploy to the family office on their machine
  with `./go`; one week of live use logged in the Ledger.
